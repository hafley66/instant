# Session: md-package-extraction-signal-boundary

## Goal
Extract Instant's Markdown renderer into publishable `@hafley66/md`, migrate Instant to the registry package, document its provenance and architecture, and clarify the existing Signals/RxJS boundary without inventing a new abstraction.

## Current State
- `@hafley66/md@0.1.0` is published on npm.
- Instant `package.json` now depends on `@hafley66/md: ^0.1.0`; `pnpm-lock.yaml` resolves the registry package.
- Instant's tracked `packages/md` directory was deleted after the registry package passed integration gates.
- Instant passed `just check`, `just build`, and `just cargo-check`; after deletion, `just check` and `just build` passed again.
- `hafley-rxjs/packages/md` contains the extracted source, Vite build configuration, declarations, tests, changelog, and a rewritten architectural README.
- The published 0.1.0 package emits `dist/style.css`, but the manifest does not export it and the compiled JS has extracted the source CSS imports. Instant therefore receives behavior without package-owned Markdown/lightbox styles. A follow-up release is required.
- `packages/signals/plans/2026-08-10-signal-epic-slice.md` is a deferred design note. No `scan$`, `impl$`, `SignalEpicSlice`, or `SignalEpic` API is implemented or exported.

## Problem/Context
The Markdown feature originated inside Instant and depended on Tauri filesystem operations, Dockview, plugin registration, Instant state, persisted plugin state, TreeTable, zoom, diagnostics, and pan/zoom. Extraction introduced `MdviewHost` as the application boundary. The user requested documentation explaining how this architecture entered the repository.

The later Signals discussion established a narrower existing model. RxJS owns temporal events from impure sources; `mergeByKey` preserves keyed event identity. `Signal` owns current BehaviorSubject-backed state, recursive path access, precise setters, and tracked memos. The user explicitly rejected additional Redux-like slices, reducer-return protocols, event mapping layers, and repeated Signal definitions. Do not propose a new API without a direct request.

## Solution/Approach
- Keep the extracted package React-based and host-integrated through `MdviewHost`.
- Use Unified plus `remark-parse` for section/list structure and Streamdown for visual Markdown rendering.
- Use Mermaid and `@terrastruct/d2` custom fence renderers plus the shared React lightbox.
- Keep Instant as the owner of filesystem I/O, Dockview composition, TreeTable, theme/dark state, per-tab zoom, persistence, and diagnostics.
- For Signals/RxJS analysis, stay with retrieved source facts: one root Signal can model current filesystem state by path; RxJS and `mergeByKey` carry impure temporal sources; subscriptions may perform precise path setters.

## Key Insights
- The package CSS uses Instant-owned variables such as `--panel-bg`, `--panel-fg`, `--frame`, `--row-hover`, and `--term-bg`; the integration contract is CSS variables plus one explicit stylesheet import.
- The installed registry package was confirmed at `node_modules/.pnpm/@hafley66+md@0.1.0...`, not linked to the deleted local package.
- Instant retains two thin `src/mdview` re-export shims and application-specific terminal diagram detection/placement. Shared D2 rendering, diagram themes, parsing, and lightbox live in `@hafley66/md`.
- `mergeByKey` already emits a discriminated `{ key, value }` union from a record of Observables. `mergeByKeyScan` retains latest values by key. Signals already expose event-mode Subject semantics through bare `Signal<T>()`, current state through BehaviorSubject semantics, recursive paths, and computed dependency tracking.
- The user wants low repetition and maximum inference from impure RxJS sources. Treat that as a constraint, not authorization to design another abstraction.
