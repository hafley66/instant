Fix matches the existing pattern at src/palette.ts:170-174 (preventDefault + stopPropagation).
- Off-by-one: never got visual evidence (macOS blocked reading the screenshot path). User tagged it "row shift on scroll" and "happening more commonly now" (regression). Suspects ranked: (a) non-integer cell height at the current font size causing xterm DOM renderer floor/ceil drift, (b) FitAddon race after the Jul-19 zoom-registry refactor `caa4145 feat(zoom): generic per-tab zoom registry` — `applyTermFontSize` at src/terminal.ts:262-267 sets `fontSize` then calls `fit()` synchronously, vs the prior direct path; fit() is also called inside requestAnimationFrame at lines 689, 737, 886 which can race render frames, (c) CSS padding/border on the term host throwing off xterm's measurement. xterm.js 6.0, addon-fit 0.11, no WebGL/Canvas addon (DOM renderer only). zoom is font-size based (not a CSS transform), so the panelZoom scale-transform hypothesis is ruled out.
- Image drag-drop: `$TMPDIR/TemporaryItems` itself returns "Operation not permitted" to the agent shell even though it's user-owned — modern macOS TCC. The user's workflow is drag-from-floating-thumbnail (no save wait), so disabling the thumbnail (first attempted fix) was wrong and was reverted. The host process tree is `target/debug/instant` (PID 36598) -> tmux -> bash -> opencode -> bash; TCC responsible party is the dev binary, so FDA must be granted there.
