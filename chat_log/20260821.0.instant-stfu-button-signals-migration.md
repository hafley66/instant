## Problem/Context

### The flat button (took ~12 rounds)
The 40-disc CSS-3D cylinder rendered as a flat circle in the user's WKWebView. Reported as "flickers as up then boom down". Every measurement I took was **Playwright WebKit, which is NOT WKWebView** — this session re-proved that the hard way, same as the earlier mermaid `foreignObject` mistake.

Four separate 3D-flattening causes existed, three of which I fixed while the real one hid in a file I never opened:

1. `@property --stfu-unit { initial-value: 0px }` — a registered custom property falls back to its `initial-value` on style recalc, and `main.ts` forces two on the tick after mount (`chrome.ts:129` `host.hidden`, `main.ts:276` `applyZoom`).
2. `.stfu-stage` carried `perspective: 520px` AND `transform: scale(0.42)`; `#stfu-host` wrapped it in a second transform.
3. `.stfu-cap` was a `<button>` at native `appearance` — a platform control renderer flattens `preserve-3d` children.
4. **`styles.css:3280`**: `body[data-skin="ac3"] button { clip-path: polygon(6px 0, ...) }`. `clip-path` flattens a 3D rendering context. First paint has no `data-skin`; `syncSkin` writes it a tick later and the cylinder collapses. The user runs the `ac3` skin.

Found only by having the user run an ancestor-chain enumeration snippet in their own devtools that printed every flattening property from `.stfu-disc` up to `<html>`.

### The config state
`state.ts` was 512 lines with `AppState` at 61 fields, 48 in a `PERSIST` list, 51 `loadKey` calls. Adding one setting cost 8 edit sites across 3 files. `panicSub`'s four legal values were spelled three times with nothing cross-checking them. `state.ts:508` rewrote all 48 localStorage keys on every `set()`.

## Solution/Approach

### Button
- `initial-value` is the resting height, never `0px`.
- No element carries `perspective` and `transform` together; the 0.42 scale moved to `#stfu-host`, the drag offset moved from a transform into `right`/`bottom` `calc()`.
- `#stfu-host .stfu-cap, .stfu-stage .stfu-cap { clip-path: none; filter: none; mask: none; backdrop-filter: none; mix-blend-mode: normal; isolation: auto }` — the `#stfu-host` id outranks any skin rule.
- Disabled-state desaturation rides `.stfu-disc`/`.stfu-top` (leaves) instead of `.stfu-cap`.
- `--stfu-unit` cascade collapsed from 5 writers at 4 specificity levels to 4 at equal specificity via `data-cap` on the stage, single writer `const state = hold ?? (hovering ? "hover" : null)`.

### Signals
Three layers, each smaller than the last:
1. `src/0_persistedSetting.ts` — `setting<T>(key, fallback)` and `cycleSetting<T>(sig, values)`. Owns `SAFE_BOOT` handling, the loadKey raw-string parity, and a **guarded storage adapter** (the library's `localStorageAdapter` calls `addEventListener` unconditionally; node test env lacks it; `statusModel.ts:20` already had this pattern).
2. `src/0_settings.ts` — all 39 durable keys, one line each, plus the four one-time migrations (`resumeTabsV2`, `clickRulesV3`, `panelZoomV1`, `meme:ui`) which must run before any signal reads storage.
3. `src/store.ts` — `createStore` backed by `Signal`, exposing `$` (the signal, for nested proxy access) and `changed$` (per-`set()` delta). `get`/`set`/`subscribe` semantics unchanged; the 8 pre-existing tests pass untouched.

**Technique that made the 39-key migration tractable**: declare everything, delete the fields from `AppState`, let `tsc` produce the worklist. 276 errors -> 0 in scripted passes (regex for `store.get().KEY`, compiler-position-driven rewrites for member accesses, hand edits for destructuring and multi-key `store.set`).

## Key Insights
- **Playwright WebKit is not WKWebView.** Burned twice now (mermaid `foreignObject`, this button). When a bug only reproduces in the user's app, stop measuring in the lab and have them run a snippet in their own devtools.
- **Enumerate instead of guessing one property at a time.** Four rounds of "is it `filter`? is it `appearance`?" cost more than one ancestor-chain dump that named `clip-path` immediately.
- Properties that flatten a 3D rendering context: `filter`, `clip-path`, `mask`, `backdrop-filter`, `opacity < 1`, `mix-blend-mode`, `isolation`, `contain`. An element with both `perspective` and `transform` is also at risk in WKWebView.
- A global `body[data-skin=...] button` rule reaches into any component that uses a `<button>`. Component CSS should opt out of flatteners explicitly with an id-level selector.
- A regression probe that never enters a state cannot catch a bug in it. The probe passed a dozen times because it never set `data-skin` and never set `cap.disabled = true`.
- **`@property` registration is required for interpolation.** An unregistered custom property is a token string and cannot animate. `initial-value` must be the resting value, never zero, or any style recalc snaps to it.
- `Signal` nested field access needs an implicit index signature: type aliases get one, `interface` does not. `AppState` is a type alias so it worked; `TestState` was an interface and did not.
- Signals replay on subscribe, which deletes the "subscribe then call once for the initial value" pattern everywhere.
- Compiler-driven refactors scale: delete the declarations first, then let `tsc` enumerate every call site.
