## Problem/Context
Dockview provides tab/group/split composition. A canvas provides free placement and layering inside a region. A Dockview panel can host a canvas, and canvas rectangles can host resources or nested canvases. Treating either Dockview or canvas as the universal parent creates an artificial direction. The emerging model is a window-system graph whose nodes describe containment and placement modes. HTML remains the rendering substrate for ordinary content; React Flow and Cytoscape remain specialized projections for spatial and graph workloads.

The design is paused because the containment algebra, layering, viewport ownership, edge interaction, persistence, and replay semantics need to be settled together.

## Solution/Approach
- Separate resource identity from placement. Terminals, files, sessions, and media retain resource identity while moving among dock, split, canvas, and window placements.
- Represent layout as a recursive graph or tree with placement modes such as dock, split, canvas, window, and resource.
- Allow a canvas node to be a layer and to contain another canvas.
- Keep Dockview as one projection/placement mode rather than making it the root ontology.
- Open the rectangle content boundary to a renderer registry keyed by serializable content references.
- Route move, resize, raise, content reconciliation, undo, and redo through the Signal event channel.
- Persist serializable resources, placements, containment edges, z order, and event history. Runtime handles such as PTYs, DOM nodes, React components, and Cytoscape instances stay outside serialized state.
- Adapt one existing terminal resource first, rendering the same resource in an ordinary Dockview tab and in a rectangle without duplicating PTY ownership.

## Key Insights
- Dockview and canvas are sibling layout projections in a larger containment graph.
- Canvas-in-canvas is meaningful as a nested layer or viewport.
- HTML can render most resource content. Specialized graph/canvas engines are selected by content and scale.

- Current package `initial` is fixed. Content changes reconstruct the model and discard journal history.
- Current controlled React Flow implementation fails raw pointer drag because node positions are not updated during dragging.
- The Flash Playwright movement test dispatches the canonical model event instead of proving pointer drag.

### Highlighter and Transcript Minimap Goal
Add an explicit highlighter mode alongside favoriting. A user can mark text or message regions while reading any supported harness transcript. Highlights are durable annotations over transcript identity and source ranges rather than mutations of captured terminal text.

Build a Codex-app-style conversation minimap for arbitrary terminal harnesses. Boop observes the tmux pane viewport, determines which transcript region is currently visible, correlates that region with normalized harness messages, and publishes the visible message/range identity. Instant renders a compressed transcript minimap with the current viewport, highlights, favorites, agent events, and message boundaries.

### Instance Timeline
1. Boop samples pane identity, pane dimensions, tmux history size, copy-mode scroll position when available, and visible captured text.
2. Boop obtains normalized messages for the harness session from its parser/session store.
3. A matcher fingerprints overlapping text fragments and projects the terminal viewport onto message IDs and character ranges.
4. Boop emits the viewport match with confidence and source provenance.
5. Instant updates a Signal containing transcript extent, visible range, annotations, and the bounded minimap window.
6. The minimap renderer compresses messages into visual bands. It renders only the current bounded range plus overscan for sufficiently long conversations.
7. Scrolling the tmux pane moves the viewport marker. Selecting the minimap requests a tmux scroll target, then a later viewport sample confirms the actual location.
8. Highlighter mode converts pointer selection into a durable annotation anchored to message identity and a normalized text range.

### Storage, Reads, Writes, and Uniqueness
- Boop owns raw tmux viewport samples and harness-to-message correlation because it already owns harness, tmux, agent-session, and SQLite access.
- SQLite stores transcript identities, viewport observations when history is requested, and annotations. High-frequency viewport samples can remain ephemeral unless recording is enabled.
- Instant owns transient hover, drag, selection, minimap overscan, and rendering state through Signals.
- A message requires a stable session-scoped identity. Terminal line numbers alone are unstable after wrapping, resizing, alternate-screen transitions, and history truncation.
- Correlation should use normalized text fingerprints plus neighboring-message order. Exact text matches remain the highest-confidence case; prompt markers, harness metadata, and LSP/parser ranges can fill gaps.
- Annotation uniqueness is `annotation id`; its semantic anchor is `(session, message, normalized range, kind)`.
- The minimap should store semantic extents and derive pixels. Resizing the pane or minimap must not rewrite transcript positions.

### Hard Cases to Preserve
- tmux copy mode exposes a scroll position, while normal mode may only expose the live viewport and history extent.
- Terminal wrapping changes with pane width, so captured row offsets cannot serve as durable message coordinates.
- Harnesses redraw spinners, status lines, streaming responses, and alternate-screen content.
- Repeated text can produce multiple exact candidates; neighboring message fingerprints and ordinal constraints disambiguate them.
- tmux history can truncate text that still exists in Boop's transcript/session database.
- Long conversations require bounded minimap rendering and a coarser aggregate representation outside the rendered window.
- A minimap seek is a requested semantic destination. Boop must translate it into harness/tmux scrolling and report the resulting observed viewport.

## 2026-08-10 Append: Multiplexer Runtime Boundary

Boop should address a tmux-like terminal/multiplexer capability rather than encode tmux commands throughout lane logic. tmux, Herdr, Zellij, and future terminal runtimes become adapters. Shelling out is a valid first implementation boundary. Boop remains a short-lived CLI and SQLite index; an adapter may address an external runtime that owns a server.

- Runtime topology is sampled data. Boop parent-agent edges and goals remain durable domain data.
- Viewport samples are ephemeral unless explicit tracing records them.
- Transcript session IDs remain separate from terminal IDs and are joined through a recorded lane/harness binding.

## 2026-08-10 Append: Grid DOM Event Routes

`@hafley66/grid` should expose one reusable DOM event constructor and route grammar for grid, row, cell, column-header, and later region events. Renderers dispatch bubbling, composed `CustomEvent` records. A top-level plane delegates once and routes events through path-shaped identities.

### Route Grammar

```text
/grid/:gridId
/grid/:gridId/row/:rowId
/grid/:gridId/row/:rowId/cell/:cellId
/grid/:gridId/column/:columnId/header
/grid/:gridId/column/:columnId/resizer
/grid/:gridId/region/:regionId
```

Actions append to the addressed entity:

```text
/grid/:gridId/row/:rowId/click
/grid/:gridId/row/:rowId/double-click
/grid/:gridId/row/:rowId/long-press
/grid/:gridId/row/:rowId/cell/:cellId/click
/grid/:gridId/column/:columnId/header/click
/grid/:gridId/column/:columnId/header/context-menu
```

### Instance Timeline

1. A pointer, keyboard, focus, context-menu, or programmatic action reaches a rendered grid entity.
2. The renderer identifies the nearest cell, row, header, resizer, region, and grid attributes.
3. `gridDomRoute` produces the canonical path.
4. `dispatchGridDomEvent` emits one namespaced DOM event from the addressed element.
5. The event crosses React component and shadow-root boundaries through bubbling and composed propagation.
6. A top-level plane parses the route and dispatches it into Signals, RxJS, URL routing, commands, or application policy.
7. Package-local behavior such as expansion and sorting may consume the same routed event or run before dispatch according to the event contract.

### Storage and Uniqueness

- `gridId` is unique inside the containing application plane.
- `rowId` is unique within a grid and comes from `getRowId`.
- `cellId` and `columnId` use the grid column definition ID.
- Routes contain stable identities and actions. They do not contain row indices, visual coordinates, or React keys.
- Full row values may appear in ephemeral event detail for convenience. Durable logs store the route plus a revision or entity snapshot when required.
- DOM attributes are the observable addressing projection. Application row objects remain owned by the grid model.
- Programmatic events use the same constructor as pointer events.

### Gesture Rules

- Action cells mark `data-grid-action`; row-level activation ignores their descendant events.
- Cell events dispatch before row fallback and carry both row and cell identity.
- Column-header events carry column identity without a row identity.
- A pending single-click is canceled when a double-click is recognized if the configured policy gives double-click precedence.
- Long press uses pointer capture, a movement threshold, and cancellation on pointerup, pointercancel, scroll, or drag initiation.
- Keyboard Enter and Space can lower to the same `open` or `click` routes as pointer interaction.
